把量化研究
变成可编排的系统

QuantCode 是一个面向量化研究与风控流程的 Agent 编排框架：用状态图管理推理，用 Schema 管理交付，用人机闸门管理风险。

不是“让模型替你交易”
而是把研究团队的判断，变成可复现、可审计、可恢复的工作流。

01
Executive thesis

投资判断先说结论

QuantCode 的价值不在于再做一个“能调用 LLM 的量化工具”，而在于将量化研究中最难产品化的部分——状态、工具权限、跨组交接、风险闸门与时间安全——纳入一个可测试的执行内核。

Core thesis

从对话，走向证据链

每一步不是一段不可复现的聊天，而是一个带输入、工具调用、状态更新、Schema 验证和 artifact 输出的节点。

Why now

Agent 的瓶颈已从“会不会推理”转为“能不能负责”

量化生产环境关心的不是一句答案，而是：它调用了什么、数据截至何时、谁批准了副作用、失败后能否恢复。

02
The problem

为什么量化团队需要“编排层”

研究链路天然不是一个函数

一个因子想法要经过匹配、规格化、评估；一份模型 PR 要经过元数据提取、风险计算、阈值判断与评论；基本面研究还要处理数据发布日期与回测时点。

如果这些步骤只存在于人和人之间的对话里，系统无法回答三个问题：状态在哪里？证据是什么？失败从哪里恢复？

The missing layer
LLM负责推理与选择
Tools负责确定性动作
State负责可恢复上下文
Schema负责交付边界
HumanGate负责副作用决策

03
Architecture

真实架构：一个可控的状态图

系统没有使用黑盒式的预构建 Agent。AgentRunner.build() 在 runner/agent_engine.py:104 组装 StateGraph；固定节点负责可观测的执行阶段，路由函数负责将运行时状态映射为下一步。

图 03.01 · 真实图拓扑。证据：runner/agent_engine.py:291–340；固定节点 llm / tool / human_gate / rlhf，truncate 按配置出现。

为什么自搭 StateGraph

现成 AgentExecutor 难以插入自定义终止条件、状态指纹、循环检测、HumanGate 与 RLHF 收集。团队先列出 7 项 gap，再逐项决定实现或跳过。

可观测可单测可恢复

为什么不写死六套 DAG

共用一个 ReAct 内核，通过 group 的 system prompt、tool allowlist 与权限规则装配业务流。仍保留线性兜底：strategy / options / fundamental 的流程天然更适合确定性链路。

同一内核并非六组都已真 ReAct
04
Safety & control

风险不是提示词，是路由规则

在量化生产环境，Agent 最危险的行为不是“回答错了一句”，而是把错误决策继续传递，或在无人审批时执行副作用动作。QuantCode 把风险控制放在图的路由层。

图 04.01 · Abort 优先于 HumanGate：死循环先停止，不把无意义状态交给人审。

五层循环检测

硬迭代上限>100
工具频率5 / 8 in window
状态指纹3 repeats
连续错误5 steps
TF-IDF 停滞cosine > .85

HumanGate 的安全默认

外部 approve/reject 映射为内部 proceed/abort；未知决策一律归一为 reject。不是“让模型自己决定要不要暂停”，而是路由满足条件后直接在节点内调用 interrupt。

Fail closed
风险不确定时，不放行。

07
Data integrity

PIT：回测不能看到未来

基本面数据最容易制造看似优秀、实则不可交易的回测结果。QuantCode 将 as_of_date 作为工具参数，并在 RAG 返回后过滤发布日期。

图 07.01 · 实现位于 tools/fundamental/pit_rag_search.py:50–54。当前过滤发生在向量检索之后，over-fetch ×3 是缓解手段。

为什么这样设计

把“数据截至何时可知”变成强制字段，而不是研究员的口头约定。每个 PITResult 同时返回候选数与被过滤数，便于审计。

仍需加强的地方

理想状态是在向量数据库 metadata 层预过滤；当前实现是先召回再剔除，存在 top_k 被未来文档挤占的边界。

10
Closing view

投资价值：一套可被验证的基础设施

QuantCode 当前最有价值的资产不是“功能数量”，而是已经形成了一个可继续扩展的控制面：业务工具可以替换，状态契约、路由闸门、审计路径和测试结构可以复用。

我们的判断
QuantCode 已经证明了“量化 Agent 编排内核”可以被做出来；下一阶段的价值创造，不是继续堆 demo，而是把真实数据、真实服务和跨组契约接上，使可演示路径变成可运营产品。
