需要人工建立与维护的结构化主表

产业地图主表

管理产业节点、层级、定义、别名、关系、研究状态和资产挂接。产业图可由主表生成，但不替代主表。

行业标的主表

区分公司实体与证券，记录产业映射、业务重要性、商业化阶段、覆盖进度和报告链接。

团队假设表

分离当前事实、市场共识和团队三情景，记录影响路径、验证指标和反证条件。

公司比较与估值矩阵

承载盈利模型、估值公式、敏感性、反向估值、预期差和横向比较。

动态跟踪表

记录关键指标、来源、频率、触发条件、触发后的研究动作和负责人。

元数据与ID规则

统一项目、节点、公司、证券、文档、假设、命题、跟踪项和References的稳定ID。

人工确认原因：这些资产涉及多工作表关系、状态维护、公式、数据验证、币种与股本口径。当前不由通用大模型直接生成最终工作簿。

输入类型典型材料缺失时的处理
研究任务立项卡、模块任务、会议记录、管理层需求标记范围和目标待确认
研究内容自由文本、笔记、报告草稿、技术分析、公司分析保留已有内容，不补造缺失分析
事实与数据年报、公告、财务表、行业数据、参数、图表标记无来源数字和口径缺口
证据文件、链接、页码、章节、References库使用unknown或pending_confirmation
结构化主表项目ID、节点ID、公司ID、证券ID、团队假设与估值矩阵不得擅自创建重复正式ID

所有 Prompt 共同遵守的输出原则

正式资产

输出可以直接保存的Markdown、YAML或JSONL，不输出需要人工重新拼装的零散段落。

缺口与风险

同步输出缺失信息、证据冲突、口径问题、逻辑跳跃和商业化夸大。

人工确认清单

把核心问题、范围、行业判断、商业化状态、估值和命题状态集中交给负责人确认。

不虚构

为了模板完整而补造事实是禁止行为；缺失字段应明确保留为空或待确认。
