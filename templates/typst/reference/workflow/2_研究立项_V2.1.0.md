## 一、阶段定位

研究项目立项阶段负责将产业地图中的某一产业节点、技术模块或阶段性专题，转化为可以正式执行的研究项目。

本阶段不负责长期维护候选主题，也不建立独立的研究主题候选池。尚未立项的产业和专题继续保留在产业地图中，通过研究状态、优先级、专题标签和备注字段管理。

本阶段只回答以下问题：

1. 本次研究为什么现在启动；
2. 本次研究准备解决什么核心问题；
3. 研究范围覆盖到哪里；
4. 最终需要形成哪些成果；
5. 由谁负责；
6. 预计使用多少时间；
7. 是否具备进入下一阶段的基本条件。

以上问题明确后，输出一份《研究项目立项卡》，项目随即进入技术与产业链拆解阶段。

---

## 二、阶段起点与终点

### 2.1 阶段起点

出现以下任一情况，并由项目总负责人决定投入正式研究资源时，启动研究项目立项：

1. 团队中期规划要求覆盖某一产业、赛道或技术方向；
2. 产业地图中存在需要补齐的核心空白；
3. 新技术、订单、政策、资本开支或供需变化可能改变产业判断；
4. 管理层提出明确研究要求；
5. 既有行业项目需要向新的上下游、技术路线或应用场景延伸；
6. 已有投资命题需要通过新的专项研究验证或修正；
7. 新出现的重要公司、产品或商业模式无法由现有研究充分解释。

立项触发信息可以记录在产业地图的专题标签、备注或研究状态中，不需要另建独立候选池。

项目尚未确定核心问题、负责人和基本资源条件时，不进入正式立项程序。

### 2.2 阶段终点

研究项目立项只有在以下事项全部完成后才算结束：

- 项目已经挂接至至少一个正式产业地图节点；
- 立项原因和唯一核心问题已经明确；
- 本轮包含范围与不包含范围已经初步确定；
- 预期交付物和可复用既有资产已经明确；
- 项目总负责人、参与成员和预计周期已经确定；
- 第一次阶段会议及首个交付节点已经确定；
- 已检查重复项目、前置依赖、资料可得性和成员资源；
- 《研究项目立项卡》已经完成并经项目总负责人确认；
- 项目状态已经更新为“待启动”，可以进入下一阶段。

未形成正式立项卡的研究方向，不得进入技术与产业链拆解阶段。

---

## 三、目标

本阶段的目标是以最低必要成本完成一次清晰的项目定义，使团队在正式开展研究前，对研究原因、研究问题、执行边界和预期成果形成一致理解。

具体目标包括：

### 3.1 将产业方向转化为研究问题

项目不能只以产业名称、技术名称或市场热点作为研究目标，而应形成一个能够通过研究得到明确回答的核心问题。

例如：

> 云厂商AI资本开支增长是否正在形成持续的液冷需求，以及价值量最可能集中于哪些产业链环节？

而不是：

> 研究液冷行业。

### 3.2 明确项目范围和完成标准

在正式分工前，明确本轮研究覆盖哪些产业节点、技术模块、应用场景和市场，以及哪些相邻问题不在本轮处理范围内，避免项目执行过程中持续扩张。

### 3.3 检查项目是否值得单独启动

确认该研究不是既有项目的重复内容，也不是可以通过局部更新、增加子课题或调用既有资产解决的问题。

### 3.4 确认项目具备执行条件

确认团队存在明确负责人、可用成员、基本资料来源、合理周期和首个节点，不在关键前置条件缺失时贸然启动。

### 3.5 建立后续流程的统一入口

通过唯一的《研究项目立项卡》，将产业地图、研究计划、项目会议、标的覆盖、研究资产和后续复盘连接起来。

---

## 四、输入

### 4.1 《长期产业地图主表》

用于确定：

- 项目属于哪个一级领域、二级赛道或三级产业；
- 是否关联某项技术模块或阶段性专题；
- 当前研究状态；
- 已有项目和研究资产；
- 相关标的覆盖情况；
- 是否已经存在相同或相近项目。

如立项过程中发现产业地图结构存在问题，应返回第一阶段提出产业节点变更，不在本阶段直接修改正式地图结构。

### 4.2 立项触发信息

立项可以由以下因素触发：

- 团队中期规划要求；
- 产业地图中的核心空白；
- 新技术、订单、政策或资本开支变化；
- 管理层提出的研究要求；
- 已有项目需要向上下游扩展；
- 已有投资命题需要重新验证；
- 新出现的重要公司或商业模式。

触发信息用于解释“为什么现在研究”，但不需要单独维护成一套候选数据库。

### 4.3 当前资源状态

立项前需要确认：

- 当前是否存在未完成的高优先级项目；
- 谁可以担任项目负责人；
- 参与成员是否有实际可用时间；
- 是否存在必要的资料来源；
- Sentinel或其他工具是否能够提供支持；
- 是否有必须先完成的前置研究。

### 4.4 已有研究资产

包括：

- 既有行业报告；
- 产业链图和技术路线资料；
- 已有标的池；
- 公司基础档案；
- 投资命题和动态跟踪记录；
- 行业Skill、Prompt和Agent；
- 历史项目复盘。

这些资产用于判断本项目应当新建立完整研究，还是在原有资产基础上更新、扩展或补充。

---

## 五、主要动作

### 5.1 选择研究对象

研究对象必须直接挂接产业地图中的至少一个正式节点，也可以同时关联技术模块或专题标签。

例如：

- 产业节点：数据中心电源；
- 技术模块：高压直流供电；
- 专题标签：AI数据中心功率密度上升；
- 正式项目：AI数据中心功率提升对供电架构及相关设备需求的影响。

### 5.2 说明立项原因

立项原因应当明确说明：

- 当前发生了什么变化；
- 为什么这一变化值得投入研究；
- 它与团队中期规划有什么关系；
- 不研究会遗漏什么判断、产业能力或投资机会。

不接受只写“行业热门”“市场关注度较高”或“近期上涨较多”。

### 5.3 提出核心问题

每个项目原则上设置一个核心问题。

核心问题应当：

- 能够在预计项目周期内得到回答；
- 与产业判断、公司覆盖或投资判断直接相关；
- 能够形成肯定、否定或条件性结论；
- 不依赖明显无法取得的关键信息；
- 不与既有项目完全重复。

核心问题之下可以设置若干初步子问题，但详细拆分由下一阶段完成。

### 5.4 初步确定研究边界

立项阶段只需要明确基本边界，包括：

- 本轮研究的主要产业节点；
- 涉及的技术模块；
- 主要需求或应用场景；
- 需要覆盖的市场；
- 需要追溯的产业链范围；
- 主要时间口径；
- 本轮明确不处理的内容。

边界的作用是确认项目能否执行，不要求在立项阶段完成详细产业链设计。

### 5.5 检查重复和已有资产

立项前必须检查：

- 是否已经存在相同项目；
- 是否可以直接更新已有研究，而不必重新立项；
- 是否只是现有项目中的一个子课题；
- 已有哪些报告、标的池、公司档案或行业Skill可以复用；
- 新项目是否会产生无必要的重复劳动。

如果只是对已有项目进行局部更新，应建立更新任务，而不是新建完整项目。

### 5.6 确定交付物

每个完整行业项目原则上需要形成：

- 行业或专题研究主文档；
- 技术路线和产业链结构；
- 行业标的池及全覆盖任务；
- 公司基础覆盖资产；
- 团队假设和估值材料；
- 投资命题；
- 动态跟踪指标；
- 行业Skill或方法总结。

验证型、更新型或范围较小的项目可以调整交付物，但任何删减都应在立项卡中说明原因。

### 5.7 确定责任和周期

明确：

- 项目总负责人；
- 参与成员；
- 预计项目周期；
- 第一次项目会议时间；
- 下一阶段的首个交付节点；
- 已知资料风险和执行风险。

立项阶段不需要完成全部子课题分工，详细分工在技术与产业链拆解阶段完成。

### 5.8 确认启动条件

项目只有满足以下条件才能启动：

- 能挂接至正式产业地图节点；
- 核心问题明确；
- 研究范围基本可控；
- 不与现有项目无意义重复；
- 有明确负责人；
- 有基本可用的资料来源；
- 当前团队资源允许启动；
- 不存在尚未解决的关键前置依赖。

## 六、输出

本阶段只有一个正式输出：

# 《研究项目立项卡》

立项卡至少包含以下字段：

| 字段 | 内容要求 |
|---|---|
| project_id | 项目唯一编号 |
| project_name | 项目正式名称 |
| related_nodes | 关联产业地图节点 |
| related_modules | 关联技术模块或专题标签 |
| trigger | 立项触发原因 |
| research_reason | 为什么当前启动 |
| core_question | 本项目唯一核心问题 |
| preliminary_subquestions | 初步子问题 |
| included_scope | 本轮包含范围 |
| excluded_scope | 本轮不包含范围 |
| target_markets | 需要覆盖的市场 |
| time_scope | 本轮研究的主要时间口径 |
| expected_deliverables | 预期交付物 |
| reusable_assets | 可复用的既有研究资产 |
| project_owner | 项目总负责人 |
| participants | 参与成员 |
| estimated_cycle | 预计项目周期 |
| first_checkpoint | 第一次阶段会议及交付要求 |
| known_risks | 已知资料、时间和执行风险 |
| dependencies | 前置项目或条件 |
| approval | 最终确认人及确认日期 |
| status | 待启动、执行中、暂停、结项或取消 |

立项卡可以使用Markdown、表单或结构化数据库记录，但必须：

- 具有唯一项目编号；
- 具有唯一正式版本；
- 能够与产业地图节点关联；
- 能够被后续研究计划、项目会议和研究资产引用；
- 在项目范围、负责人或周期发生重大变化时保留更新记录。

## 七、负责人

### 7.1 项目总负责人

负责：

- 发起或确认项目立项；
- 判断研究方向是否符合团队中期规划；
- 确认核心问题和初步边界；
- 判断是否需要新建立完整项目；
- 确认项目总负责人、参与成员和预计周期；
- 审核预期交付物；
- 处理资源冲突和前置依赖；
- 最终批准《研究项目立项卡》。

### 7.2 研究成员

负责：

- 参与讨论核心问题和研究边界；
- 说明资料可得性、技术难度和预计工作量；
- 申报真实可用时间；
- 指出现有资产、重复研究和潜在执行风险；
- 确认自己在下一阶段能够承担的任务。

研究成员在立项阶段不需要完成正式子课题分工。

### 7.3 AI工具与Sentinel

负责辅助：

- 检索已有相同或相近研究；
- 返回相关产业地图节点；
- 汇总已有报告、公司和标的池；
- 检查资料来源和自动化支持条件；
- 提醒可能存在的重复项目或关键资料缺口；
- 根据讨论内容生成立项卡初稿；
- 检查立项卡字段完整性。

AI工具不得独立决定项目是否立项、研究边界、人员配置和资源投入。

---

## 八、验收标准

### 8.1 产业地图挂接有效

- 项目至少关联一个正式产业地图节点；
- 技术模块和专题标签使用正确；
- 项目名称与产业地图分类不存在明显冲突；
- 如发现地图结构问题，已经返回第一阶段处理。

### 8.2 立项原因充分

- 已说明当前触发变化或战略需求；
- 已说明为什么需要在当前时间启动；
- 已说明项目与团队中期规划的关系；
- 立项理由不只依赖市场热度或短期涨跌。

### 8.3 核心问题明确

- 项目只有一个主要核心问题；
- 核心问题能够通过本项目形成明确结论；
- 核心问题与产业、公司或投资判断直接相关；
- 不属于“了解行业”“整理资料”等纯描述性任务。

### 8.4 研究边界可执行

- 包含范围与不包含范围均已填写；
- 涉及的产业节点、市场和时间口径明确；
- 项目范围能够在预计周期和人员条件下完成；
- 不要求在立项阶段完成尚未进行的详细技术拆解。

### 8.5 重复与依赖已经处理

- 已检索既有项目和研究资产；
- 已判断项目应新建、更新、扩展还是作为子课题；
- 可复用资产已经列入立项卡；
- 不存在未解决的关键前置依赖。

### 8.6 资源与时间可行

- 项目总负责人已经确定；
- 参与成员具有实际可用时间；
- 预计周期与项目范围基本匹配；
- 第一次会议和首个交付节点明确；
- 已知风险已经记录。

### 8.7 立项卡完整有效

- 所有必填字段已经填写；
- 项目编号唯一；
- 最终确认人和确认日期明确；
- 项目状态已更新为“待启动”；
- 立项卡能够被下一阶段直接引用。

---

## 九、自动化潜力

本阶段不需要开发复杂的主题筛选Agent。

AI或Sentinel可以辅助：

- 检索已有相同或相近研究；
- 返回相关产业地图节点；
- 汇总已有报告、公司和标的池；
- 检查立项卡字段是否完整；
- 根据会议内容生成立项卡初稿；
- 提醒可能存在的重复项目或资料缺口；
- 初步估计后续公司覆盖和资料整理工作量。

以下事项必须由项目总负责人决定：

- 是否启动项目；
- 为什么现在研究；
- 核心问题是什么；
- 研究边界如何设置；
- 谁负责项目；
- 项目使用多少资源；
- 是否暂停或取消项目。

---

## 十、本阶段不负责的事项

研究项目立项阶段不负责：

- 完成详细技术路线研究；
- 绘制正式产业链；
- 制定完整子课题分工；
- 建立行业标的池；
- 完成公司基础覆盖；
- 形成估值模型；
- 作出正式投资命题；
- 决定实际仓位和组合配置。

上述工作由后续阶段分别完成。

---

## 十一、本阶段完成定义

研究项目立项阶段完成，应达到以下状态：

> 项目已经从产业地图中的一个明确节点、技术模块或专题出发，形成唯一的《研究项目立项卡》；立项原因、核心问题、初步边界、预期交付物、负责人、周期和首次节点均已明确；项目不存在未经处理的重复研究、资源冲突或关键前置条件缺失，可以直接进入技术与产业链拆解阶段。
