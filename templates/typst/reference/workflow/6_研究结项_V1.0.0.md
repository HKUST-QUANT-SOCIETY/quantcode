## 一、阶段定位

本阶段是行业研究项目的最终阶段。

前五阶段已经完成：

1. 产业地图维护；
2. 研究项目立项；
3. 技术与产业链拆解及研究；
4. 标的池建立与公司标准化全覆盖；
5. 团队假设、行业综合判断与投资命题形成。

因此，本阶段不再以新增研究内容为主要任务，而是完成以下四项工作：

1. **研究结项**：确认项目已经完成到什么程度，哪些结论成立，哪些问题仍未解决；
2. **资产沉淀**：将项目成果整理为可复用、可检索、可更新的长期研究资产；
3. **动态跟踪**：将关键假设、风险、催化和反证条件转化为持续跟踪对象；
4. **项目复盘**：复盘研究方法、团队分工、资料质量和自动化能力，形成下一轮改进。

本阶段的核心目标是：

> 将一次性研究项目转化为长期可调用的研究资产和可持续更新的行业认知。

本阶段不负责：

- 实际买入或卖出；
- 仓位配置；
- 组合风险预算；
- 交易时点；
- 止盈止损；
- 交易绩效归因。

这些事项属于独立的投资管理流程。

## 二、阶段起点与终点

### 2.1 阶段起点

本阶段从第五阶段通过验收后开始。

进入本阶段前，应至少具备：

- 完整的《行业研究主文档》；
- 完整的《行业标的主表》；
- 池内正式标的的《公司标准化研究报告》；
- 《行业综合投资判断》；
- 《公司比较与估值矩阵》；
- 已形成或已明确不形成的《投资命题卡》；
- 项目过程中的会议记录；
- 原始资料、数据、模型和图表；
- 当前尚未解决的问题和资料缺口。

如果第五阶段的行业判断、估值或投资命题尚未完成，不应提前进入正式结项。

### 2.2 阶段终点

本阶段只有在以下事项全部完成后才算结束：

- 项目最终结论和未解决问题已经确认；
- 项目成果已经按统一目录和命名规范归档；
- 产业地图中的研究状态和资产链接已经更新；
- 行业标的主表和公司报告的版本状态已经更新；
- 投资命题状态已经确认；
- 关键假设、催化、风险和反证条件已经转化为动态跟踪指标；
- 每项动态跟踪指标已经明确来源、频率、负责人和触发条件；
- 项目复盘已经完成；
- 可沉淀的行业Skill、Prompt、模板或Sentinel需求已经记录；
- 项目后续状态已经确认；
- 项目总负责人批准《项目结项与跟踪包》。

## 三、目标

### 3.1 正式结束项目执行状态

项目应从“执行中”转为明确的后续状态，避免长期停留在模糊的“尚未完全完成”。

项目结项不等于所有问题均已得到答案。

只要以下事项已经明确，即可结项：

- 已经回答的核心问题；
- 尚未回答的问题；
- 当前结论的置信度；
- 后续需要等待的证据；
- 动态跟踪机制；
- 重新启动条件。

### 3.2 将成果转化为长期研究资产

研究成果应具备：

- 清晰的文件结构；
- 统一的命名；
- 明确的版本；
- 可追溯的来源；
- 与产业地图、标的池和公司档案的链接；
- 便于新成员理解；
- 便于AI工具检索和更新；
- 便于未来项目复用。

### 3.3 建立轻量、有效的动态跟踪机制

动态跟踪不应变成持续重做行业研究。

只跟踪能够影响以下事项的关键变量：

- 行业核心假设；
- 技术路线；
- 需求和供给；
- 产品价格；
- 公司盈利；
- 估值；
- 投资命题；
- 反证条件。

### 3.4 保持投资命题可验证和可更新

每项投资命题都应有：

- 当前状态；
- 关键验证指标；
- 下一次检查时间；
- 催化剂；
- 风险；
- 反证条件；
- 状态变更规则。

### 3.5 通过复盘改进下一轮研究

复盘不只是记录“完成了什么”，而应判断：

- 哪些研究内容真正有用；
- 哪些工作重复；
- 哪些资料质量较低；
- 哪些分工不合理；
- 哪些环节可以自动化；
- 哪些模板需要修改；
- 哪些判断最终被验证或证伪。

## 五、主要动作

本阶段按照四个连续子流程执行：

1. 研究结项；
2. 资产沉淀；
3. 动态跟踪；
4. 项目复盘。

# A. 研究结项

### 5.1 复核立项目标

项目总负责人对照《研究项目立项卡》，逐项确认：

- 核心问题是否得到回答；
- 初始研究边界是否发生变化；
- 预期交付物是否已经完成；
- 哪些问题被证明不重要；
- 哪些问题仍然重要但暂时无法回答；
- 是否存在超出原立项范围的新增成果；
- 是否需要为剩余问题重新立项。

### 5.2 形成项目最终结论

项目最终结论应简明回答：

- 行业处于什么阶段；
- 核心需求和技术判断是什么；
- 产业链价值如何分布；
- 哪些公司具有实质暴露；
- 团队核心假设是什么；
- 市场主要预期差是什么；
- 是否形成投资命题；
- 当前最大的风险和不确定性是什么。

最终结论不重新撰写完整研究报告，而是对整个项目进行压缩总结。

### 5.3 记录未解决问题

未解决问题至少包括：

| 字段 | 内容要求 |
|---|---|
| unresolved_id | 问题唯一编号 |
| question | 尚未解决的问题 |
| importance | 对行业、公司或命题的重要程度 |
| missing_evidence | 当前缺失的证据 |
| expected_source | 未来可能获得信息的来源 |
| review_trigger | 重新检查的触发条件 |
| owner | 跟踪负责人 |
| status | 等待验证、暂无法回答、已转新项目或不再重要 |

未解决问题不应隐藏在报告正文中，应集中列入结项包。

### 5.4 确认项目后续状态

项目结项后，状态只能为以下之一：

#### 持续跟踪

适用于：

- 行业仍然重要；
- 已形成投资命题；
- 核心变量需要持续更新；
- 行业和公司变化较快。

#### 等待验证

适用于：

- 研究已经完成；
- 当前缺少关键订单、客户、技术或财务证据；
- 暂时不需要持续高频跟踪。

#### 暂停

适用于：

- 项目重要性下降；
- 团队资源不足；
- 关键前提短期内无法验证；
- 需要等待外部条件。

#### 已归档

适用于：

- 行业变化较慢；
- 当前没有投资命题；
- 研究资产仍有长期参考价值；
- 只需低频复核。

#### 重新立项

适用于：

- 原项目范围已经无法覆盖新问题；
- 技术路线或产业边界发生实质改变；
- 出现独立且重要的新研究问题。

项目状态必须由项目总负责人确认。

# B. 资产沉淀

### 5.5 建立统一项目目录

建议项目目录至少包含：

```text
项目名称/
├── 00_立项与管理/
│   ├── 项目立项卡
│   ├── 分工记录
│   └── 会议记录
├── 01_行业研究/
│   ├── 行业研究主文档
│   ├── 技术路线
│   ├── 产业链图
│   └── 模块研究文档
├── 02_标的池与公司覆盖/
│   ├── 行业标的主表
│   └── 公司标准化研究报告
├── 03_综合判断与投资命题/
│   ├── 行业综合投资判断
│   ├── 公司比较与估值矩阵
│   └── 投资命题卡
├── 04_动态跟踪/
│   ├── 动态跟踪表
│   ├── 更新记录
│   └── 未解决问题
├── 05_复盘与沉淀/
│   ├── 项目复盘
│   ├── 资产清单
│   ├── Prompt与工具需求
│   └── Skill草案
└── 99_原始资料/
    ├── 公司资料
    ├── 行业资料
    ├── 数据
    └── 其他材料
```

目录可以根据现有文件系统调整，但不同项目应尽量保持一致。

### 5.6 统一文件命名和版本

建议格式：

```text
[项目编号]_[文档类型]_[主题或公司]_[版本]_[日期].[扩展名]
```

例如：

```text
CPO_行业研究主文档_V1.0_20260623.md
CPO_公司研究_中际旭创_V1.0_20260623.md
CPO_投资命题_中际旭创_V1.0_20260623.md
```

版本管理原则：

- 重大结构或结论变化：升级主版本；
- 数据更新或小幅修改：升级次版本；
- 历史版本保留，不覆盖删除；
- 当前有效版本应明确标记。

### 5.7 建立《研究资产清单》

每项正式资产至少记录：

| 字段 | 内容要求 |
|---|---|
| asset_id | 资产唯一编号 |
| asset_name | 资产名称 |
| asset_type | 行业报告、公司报告、模型、图表、命题卡、Prompt、Skill等 |
| related_project | 所属项目 |
| related_nodes | 关联产业地图节点 |
| related_companies | 关联公司 |
| version | 当前版本 |
| owner | 维护人 |
| file_path | 文件位置 |
| status | 有效、待更新、过期、归档 |
| latest_update | 最近更新时间 |
| update_trigger | 需要更新的条件 |
| notes | 其他说明 |

短期可以使用表格管理，不要求单独开发复杂资产系统。

### 5.8 更新产业地图

本阶段需要将项目结果反馈至第一阶段产业地图。

至少更新：

- `research_status`；
- `latest_update`；
- `related_projects`；
- `related_assets`；
- `related_companies`；
- `owner`；
- `notes`；
- 下次复核时间。

研究状态可以更新为：

- 基础覆盖完成；
- 完整研究完成；
- 持续跟踪；
- 等待验证；
- 暂停；
- 已归档。

### 5.9 更新标的主表与公司报告

至少更新：

- 公司覆盖状态；
- 最新报告版本；
- 最近更新时间；
- 主要资料缺口；
- 下一次复核条件；
- 是否关联投资命题；
- 动态跟踪状态。

### 5.10 形成可复用方法资产

项目中形成的以下内容可以单独沉淀：

- 行业研究问题清单；
- 公司覆盖行业特定字段；
- 数据提取规则；
- 估值方法；
- Prompt；
- Sentinel规则；
- 代码和脚本；
- 行业术语表；
- 行业Skill草案。

不是每个项目都必须形成完整Skill。只有具备重复使用价值的内容才需要沉淀。

# C. 动态跟踪

### 5.11 确定跟踪对象

动态跟踪只覆盖能够改变研究结论的关键对象。

可以包括：

#### 行业假设

- 需求；
- 资本开支；
- 技术渗透；
- 产品价格；
- 供给和产能；
- 市场份额；
- 政策和监管。

#### 公司经营

- 收入；
- 毛利率；
- 订单；
- 客户；
- 产品认证；
- 产能；
- 库存；
- 应收账款；
- 资本开支；
- 现金流。

#### 估值与市场预期

- 一致预期；
- 盈利预测变化；
- 当前估值；
- 历史分位；
- 可比公司估值；
- 市场对催化剂的定价。

#### 投资命题

- 催化剂；
- 反证条件；
- 重新评估条件；
- 命题置信度；
- 命题状态。

### 5.12 建立《动态跟踪表》

每项跟踪对象至少记录：

| 字段 | 内容要求 |
|---|---|
| tracking_id | 跟踪项唯一编号 |
| category | 行业、公司、估值、命题或风险 |
| indicator | 跟踪指标 |
| related_assumption | 关联团队假设 |
| related_company | 关联公司 |
| related_thesis | 关联投资命题 |
| current_value | 当前值或状态 |
| base_expectation | 团队基准预期 |
| source | 数据来源 |
| frequency | 更新频率 |
| trigger_condition | 触发条件 |
| action_if_triggered | 触发后的动作 |
| owner | 负责人 |
| latest_update | 最近更新时间 |
| next_review | 下次复核时间 |
| status | 正常、接近触发、已触发、暂停 |

### 5.13 设置跟踪频率

跟踪频率应根据变量变化速度确定。

#### 事件触发

适用于：

- 重大公告；
- 客户认证；
- 大额订单；
- 技术突破；
- 政策变化；
- 收购和融资；
- 投资命题反证。

#### 周度或双周

适用于：

- 高频价格；
- 订单和出货线索；
- 市场一致预期变化；
- 行业动态。

#### 月度

适用于：

- 产量；
- 市场数据；
- 海关数据；
- 价格和库存；
- 项目建设进度。

#### 季度

适用于：

- 财务数据；
- 毛利率；
- 现金流；
- 应收和存货；
- 资本开支；
- 公司指引。

#### 半年或年度

适用于：

- 产业地图结构；
- 长期技术路线；
- 行业竞争格局；
- 完整公司覆盖更新。

不要求所有指标高频更新。

### 5.14 设置触发条件

触发条件应尽量具体，例如：

- 客户资本开支较团队基准低10%以上；
- 产品认证延迟超过一个季度；
- 公司毛利率连续两个季度低于基准假设；
- 存货或应收增速显著高于收入增速；
- 公司市场份额下降；
- 竞争对手提前量产；
- 当前估值超过乐观情景估值；
- 订单或收入达到投资命题预设验证标准。

### 5.15 设置触发后的动作

触发后可采取：

- 更新数据；
- 更新公司报告；
- 调整团队假设；
- 修改情景盈利；
- 调整估值；
- 修改投资命题；
- 降低命题置信度；
- 取消命题；
- 重新立项研究；
- 提交投资管理流程讨论。

触发动态跟踪不代表自动进行交易。

### 5.16 管理投资命题状态

投资命题状态建议包括：

- 草案；
- 有效；
- 等待验证；
- 置信度下降；
- 已证伪；
- 已关闭；
- 已转投资决策；
- 已归档。

每次状态变化应记录：

- 变化日期；
- 变化原因；
- 新证据；
- 对盈利和估值的影响；
- 下一步动作。

---

# D. 项目复盘

### 5.17 复盘研究判断

复盘内容包括：

- 初始核心问题是否正确；
- 哪些假设最重要；
- 哪些假设被验证；
- 哪些假设被证伪；
- 哪些结论依赖了错误或过时资料；
- 哪些风险被遗漏；
- 哪些研究内容最终没有使用；
- 哪些公司被遗漏或错误纳入。

结项时无法验证的判断，应标记为“待后续验证”，不能强行判断正确或错误。

### 5.18 复盘研究流程

至少讨论：

- 立项是否清晰；
- 研究范围是否过宽或过窄；
- 子课题分工是否合理；
- 任务工作量是否均衡；
- 会议频率是否有效；
- 是否存在重复研究；
- 公司覆盖是否充分；
- 第五阶段假设和估值讨论是否顺畅；
- 哪些环节管理成本过高。

### 5.19 复盘资料和证据质量

检查：

- 最有价值的资料来源；
- 低质量或误导性来源；
- 资料获取困难；
- 关键数据缺失；
- 口径冲突；
- 公司披露不足；
- AI生成错误；
- 哪些原始资料应长期保留。

### 5.20 复盘自动化工具

至少记录：

- Sentinel哪些功能有效；
- 哪些字段提取错误较多；
- 哪些任务适合继续自动化；
- 哪些任务必须保留人工判断；
- 哪些Prompt需要调整；
- 哪些新工具值得开发；
- 自动化实际节省了多少工作；
- 是否产生额外复核成本。

### 5.21 形成改进行动

复盘不能只记录问题，还应形成可执行改进项。

每项改进至少包括：

| 字段 | 内容要求 |
|---|---|
| improvement_id | 改进项编号 |
| issue | 当前问题 |
| impact | 对研究质量或效率的影响 |
| proposed_change | 建议改进 |
| applicable_stage | 适用阶段 |
| owner | 负责人 |
| priority | 高、中或低 |
| deadline | 预计完成时间 |
| status | 待处理、进行中、已完成或不采纳 |

## 八、验收标准

### 8.1 结项状态明确

- 立项目标已经复核；
- 最终结论已经形成；
- 未解决问题已经记录；
- 项目后续状态已经确认；
- 结项日期和确认人明确。

### 8.2 研究资产完整

- 正式交付物均已归档；
- 文件命名和版本统一；
- 历史版本未被覆盖删除；
- 原始资料和正式成果得到区分；
- 所有正式资产均可打开和检索；
- 不存在关键文件只保存在个人本地的情况。

### 8.3 资产可以复用

- 资产与产业地图节点挂接；
- 公司报告与标的主表挂接；
- 投资命题与公司和假设挂接；
- 新成员能够理解目录和主要结论；
- AI工具能够读取主要文档；
- 未来项目可以直接调用已有成果。

### 8.4 动态跟踪有效

- 只跟踪能够改变核心结论的关键指标；
- 每个指标有来源、频率、负责人和触发条件；
- 触发后的动作明确；
- 不存在无人维护的高频指标；
- 跟踪成本与研究价值匹配。

### 8.5 投资命题状态清晰

- 每项命题有当前状态；
- 催化剂和反证条件明确；
- 下一次复核时间明确；
- 状态变化可追溯；
- 已证伪或已关闭命题没有继续作为有效结论使用。

### 8.6 产业地图和数据库已更新

- 研究状态正确；
- 最新更新时间正确；
- 项目和资产链接完整；
- 相关公司和负责人已更新；
- 下一次复核时间明确。

### 8.7 复盘形成改进

- 复盘覆盖判断、流程、资料、分工和自动化；
- 问题不只停留在描述；
- 改进项有负责人和优先级；
- 适用于其他项目的经验已经沉淀；
- 不值得继续维护的流程或资产得到删除或简化。

### 8.8 阶段边界清晰

- 不在本阶段执行交易；
- 不决定仓位；
- 不进行组合风险管理；
- 不以股价表现代替研究复盘；
- 研究结项和投资管理保持独立。

---

## 九、动态跟踪设计原则

### 9.1 关键指标优先

只跟踪可能改变以下事项的指标：

- 行业核心假设；
- 公司盈利；
- 合理估值；
- 投资命题；
- 主要风险。

### 9.2 事件触发优先于固定高频更新

对于变化频率较低的行业，不应为了形式每天更新。

### 9.3 跟踪指标必须对应动作

没有触发后动作的指标不应列为正式跟踪项。

### 9.4 跟踪状态不等于交易信号

跟踪指标触发后，先更新研究判断，再决定是否提交投资管理流程。

### 9.5 跟踪成本必须可控

如果一个指标难以获取、更新成本高且对结论影响有限，应降低频率或删除。

---

## 十、资产沉淀设计原则

### 10.1 正式资产与过程材料分开

正式研究成果需要稳定、可引用；过程材料可以保留，但不应与正式版本混淆。

### 10.2 资产沉淀以复用价值为标准

不是所有笔记、聊天记录和临时表格都需要成为长期资产。

### 10.3 一个事实只保留一个主要维护位置

例如：

- 公司基础事实主要维护在公司标准化研究报告；
- 公司范围主要维护在行业标的主表；
- 行业状态主要维护在产业地图；
- 投资命题主要维护在投资命题卡。

避免同一事实在多份文档中分别维护。

### 10.4 版本更新而非重复创建

行业发生变化时，应优先更新已有资产版本，而不是新建大量平行文档。

### 10.5 Skill、Prompt和工具是二次资产

只有在研究方法已经相对稳定、具备重复使用价值后，才形成Skill、Prompt或自动化工具。

---

## 十一、项目复盘设计原则

### 11.1 研究结果和研究过程分别复盘

判断正确不代表流程合理；判断错误也不代表所有研究工作无效。

### 11.2 不以短期股价判断研究质量

研究复盘重点检查：

- 假设；
- 证据；
- 逻辑；
- 估值；
- 风险；
- 反证。

### 11.3 区分可控错误和不可控变化

可控错误包括：

- 数据错误；
- 资料遗漏；
- 逻辑跳跃；
- 分工不合理；
- 估值口径错误。

不可控变化包括：

- 突发政策；
- 地缘政治；
- 技术突破；
- 客户战略变化。

### 11.4 复盘应服务下一轮执行

复盘结果应能够修改：

- 产业地图；
- 流程规格；
- 公司覆盖模板；
- Prompt；
- Sentinel；
- 会议和分工方式。

---

## 十二、自动化潜力

### 12.1 高度适合自动化的内容

- 文件清点；
- 目录整理；
- 版本和命名检查；
- 资产清单生成；
- References检查；
- 跟踪指标抽取；
- 数据更新；
- 命题状态提醒；
- 触发条件监测；
- 产业地图链接检查；
- Skill和Prompt草案生成。

### 12.2 适合Prompt工具包的内容

可以建立：

1. 项目结项检查Prompt；
2. 研究资产分类Prompt；
3. 动态跟踪指标提取Prompt；
4. 反证条件转跟踪项Prompt；
5. 项目复盘Prompt；
6. 流程问题诊断Prompt；
7. Skill生成Prompt；
8. Prompt和Agent需求提取Prompt；
9. 产业地图更新检查Prompt；
10. 项目重新立项判断Prompt。

### 12.3 必须人工判断的内容

- 是否结项；
- 最终结论；
- 项目状态；
- 关键跟踪指标；
- 触发后的研究动作；
- 投资命题状态；
- 是否重新立项；
- 哪些改进值得实施。

## 十三、异常处理

### 13.1 项目仍有大量未解决问题

判断这些问题是否影响核心结论：

- 若影响核心结论，返回前序阶段补充；
- 若不影响当前结论，记录后结项；
- 若形成独立问题，另行立项。

### 13.2 文件和资产过多

只将正式成果和高复用价值内容列为正式资产，过程文件保留但不进入核心资产清单。

### 13.3 动态跟踪指标过多

只保留能够改变假设、盈利、估值或命题的指标，其余删除或降为低频参考。

### 13.4 没有投资命题

仍可正常结项，形成否定性行业判断和重新评估条件。

### 13.5 投资命题已被证伪

更新命题状态、记录反证和影响，并保留历史版本用于复盘。

### 13.6 研究完成后行业发生重大变化

如果原结论仍可局部更新，则升级资产版本；如果行业边界、技术路线或核心问题发生变化，则重新立项。

### 13.7 无人维护动态跟踪

减少指标、降低频率或将项目状态调整为等待验证、暂停或归档。不得建立无人负责的跟踪机制。

### 13.8 Sentinel更新结果与人工判断冲突

保留原始更新结果，由负责人核验数据源和口径后决定是否修改正式资产。

---

## 十四、本阶段不负责的事项

本阶段不负责：

- 实际交易；
- 仓位配置；
- 组合风险预算；
- 交易时点；
- 止盈止损；
- 持仓调整；
- 交易绩效归因；
- 组合层面复盘。

本阶段只负责研究项目的关闭、沉淀、跟踪和研究方法复盘。

---

## 十五、本阶段完成定义

研究结项、资产沉淀、动态跟踪与复盘阶段完成，应达到以下状态：

> 团队已经正式结束项目执行状态，确认了最终结论、未解决问题和后续状态；所有正式研究成果已经按照统一目录、命名和版本规则归档，并与产业地图、标的池、公司报告和投资命题建立链接；关键行业假设、公司指标、催化剂、风险和反证条件已经转化为具有来源、频率、负责人和触发动作的动态跟踪项；项目判断、分工、资料质量、流程和自动化工具已经完成复盘，并形成可执行改进事项；项目已经从一次性研究任务转化为可复用、可更新和可持续跟踪的长期研究资产。
