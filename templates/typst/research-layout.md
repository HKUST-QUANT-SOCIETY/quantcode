## 1. 页面与品牌（封面 + 页眉页脚）

来源：`reference/workflow/0_产业研究六阶段工作流_V1.1.1.html` 与 Prompt 工具包总览 HTML 的 CSS。

### 1.1 纸张与边距

| 项 | 规格 |
|----|------|
| 纸张 | A4（210mm × 297mm） |
| 内容区边距 | 上 25.4mm · 下 25.4mm · 左 31.8mm · 右 31.8mm |
| 页眉区 | 距顶 12mm，高 13mm，左右与内容区对齐 |
| 页脚区 | 距底 12mm，高 10mm |

### 1.2 字体

| 用途 | 字体 |
|------|------|
| 中文正文 | 楷体（`KaiTi` / `楷体_GB2312`） |
| 英文与数字 | Times New Roman |
| 实现方式 | 中西文分 `unicode-range` 混排（HTML 里称 QS-KaiTi-CJK + QS-Times-Latin） |

Typst 落地建议：`#set text(font: ("Times New Roman", "KaiTi"), size: 10.2pt, lang: "zh")`

### 1.3 品牌色

| 角色 | 色值 | 用途 |
|------|------|------|
| 主色（中金红） | `#9B1E24` | 封面 kicker、一级标题下划线、页眉分隔线、强调块左边框 |
| 深酒红 | `#641018` | 深色强调 |
| 正文墨黑 | `#111111` | 主标题 |
| 正文灰 | `#3A3A3A` | 段落 |
| 辅助灰 | `#5E5E5E` | 页眉、表头说明 |
| 暖纸底 | `#F8F5F1` | 信息卡片、表头背景 |
| 科技蓝 | `#1F3A5F` | 流程图「技术/数据」节点 |
| 金色 | `#B88A2E` | 产出物高亮、估值相关块 |

### 1.4 封面（Cover）

```
┌─────────────────────────────────────┐
│ [Logo 左对齐，宽约 62mm]              │
│                                     │
│         （约 36mm 留白）              │
│                                     │
│ KICKER（9pt 全大写，主色红）          │
│ 主标题（25pt 粗体）                   │
│ 副标题（17pt 灰色，可选）             │
│                                     │
│ ─── 红色横条（高约 1.8mm）───         │
│                                     │
│ [2×2 元信息卡片 grid]                │
│  版本 / 文档角色 / 负责人 / 日期      │
│                                     │
│ [可选：callout 提示框]                │
└─────────────────────────────────────┘
```

**封面必备字段**（映射 `ResearchSpec` / YAML front matter）：

- 报告类型（公司研究 / 行业研究 / 工作流说明）
- 公司名 + 证券代码（如 `2097.HK`）
- 版本号（`V0.1` draft）
- 估值日 / 报告日
- 负责人、复核人

### 1.5 页眉 / 页脚（正文页）

| 位置 | 内容 | 样式 |
|------|------|------|
| **页眉左** | 英文小节名（如 `Workflow Map`） | 8.5pt 灰色 |
| **页眉右** | 中文小节名（如 `各阶段的核心任务`） | 8.5pt 灰色 |
| **页眉下** | 1.2px 主色红线 | 全宽 |
| **页脚左** | `HKUST-MAFM Quant Trading Society · …` | 8pt `#777` |
| **页脚右** | 页码（两位，`01` `02`…） | 8pt |
| **页脚上** | 1px 浅灰分隔线 | 全宽 |

正文区需在页眉下方再留 `padding-top: 13mm`，避免压字。

## 2. 章节结构（目录与正文层级）

来源：`reference/prompt-toolkit/05_公司标准化研究报告Prompt.md`（公司报告正文模板）。

### 2.1 公司研究报告标准目录（10 + 附录）

这是 **fundamental `research-pdf` 流** 的主线章节，Typst 模板应按此顺序预留 slot：

| 序号 | 章节 | 内容要点 |
|------|------|----------|
| 0 | YAML Front Matter | `document_id`, `company_id`, `security_ids`, `valuation_date`, `source_refs`… |
| 1 | **公司结论摘要** | 本质、核心兑现、优势、问题、估值状态 |
| 2 | **公司概览与商业模式** | 产品、客户、收入模式、增长引擎 |
| 3 | **行业映射与受益路径** | 产业链位置、需求传导至订单/利润 |
| 4 | **产品、客户与商业化证据链** | 技术储备→送样→订单→收入（分级，禁止夸大） |
| 5 | **竞争格局** | 直接竞争、替代、客户自研 |
| 6 | **收入、毛利与费用拆解** | 分业务/地区、扣非、非经常性损益 |
| 7 | **现金流与资产质量** | 应收、存货、经营现金流、CAPEX、ROE/ROIC |
| 8 | **管理层、治理与资本配置** | 指引兑现、股权激励、并购分红 |
| 9 | **当前估值与市场隐含预期** | 历史/可比估值、一致预期、**不写目标价与评级** |
| 10 | **主要风险** | 行业/技术/客户/财务/治理/估值 |
| 附 | 待验证事项 | `pending_confirmation` 清单 |
| 附 | References | Reference ID 列表 |
| 附 | 结构化数据附件建议 | 建议单独落 Excel 的表字段 |
| 附 | 缺失信息与证据冲突 | 口径问题、来源冲突 |
| 附 | 必须人工确认 | 商业化阶段、估值口径等 |

### 2.2 标题层级（Typst 映射）

| 层级 | HTML/CSS | Typst 建议 | 样式 |
|------|----------|------------|------|
| H1 | `h1` 25pt | `#heading(level: 1)` | 墨黑粗体，封面专用 |
| H2 | `h2` 18pt 红色 | `#heading(level: 2)` | 主色红 + 底部分隔线 `#EFE8DF` |
| H3 | `h3` 13.2pt | `#heading(level: 3)` | 深灰 `#262626` |
| H4 | `h4` 10.5pt | `#heading(level: 4)` | 深灰，小节标题 |
| 正文 | `p` 10.2pt | 默认 `text` | 行高约 1.62 |
| 列表 | `li` 9.5–9.7pt | `- item` | 行高约 1.45–1.48 |

## 3. 图表规范

### 3.1 通用规则

| 项 | 规则 |
|----|------|
| 图题位置 | 图下方（HTML 用 `.output-box` 金色边框突出「主要产出」） |
| 表头 | 背景 `#F8F5F1`，底边 1.3px `#D9D9D9` |
| 表格字号 | 8.6–8.8pt |
| 单元格 | 左对齐，行高 1.4，适当 `padding` |
| 双栏 | 复杂对比可用 `grid-2`（两列等宽，gap 5mm） |

### 3.2 常用图表类型

| 类型 | 场景 | 备注 |
|------|------|------|
| 流程图 `.flow` | 研究阶段、Prompt 链路 | 节点 + 箭头，红/蓝/金/绿四色语义 |
| 元信息卡 `.meta-card` | 封面、摘要页 KPI | 暖纸底 + 细边框 |
| 产出高亮 `.output-box` | 阶段主要交付物 | 金色边框 `#B88A2E` |
| 数据表 `.table` | 财务拆解、可比估值 | 数字右对齐列建议等宽字体 |

### 3.3 财务数据与 Excel 的分工

估值矩阵、盈利模型、动态跟踪表等 **不进 PDF 正文全文**，而在：

- 正文引用「见估值矩阵 `SEC-xxx`」
- 「结构化数据附件建议」章节列出表名
- 实际文件走 `人工模板规范附件/`（Excel 规范）

这是刻意的**痛点设计**：AI 写叙述，人填 Excel，避免模型编造表格数字。

## 4. 脚注与引用（References）

### 4.1 引用体系

| 概念 | 说明 |
|------|------|
| **Reference ID** | 格式 `REF-主题-序号`（如 `REF-CPO-0012`） |
| **绑定规则** | 重要事实和数字必须绑定 Reference ID |
| **三类表述** | 事实 / 推断 / 市场共识 —— **必须分开写** |
| **不确定** | 用 `pending_confirmation`，禁止为填模板而编造 |

### 4.2 Prompt 侧（`01_References整理Prompt.md`）

产出 `references.jsonl`，包含：来源、页码、证据映射、引用风险、人工确认项。

### 4.3 PDF 侧（Typst 落地建议）

| 方式 | 适用 |
|------|------|
| 上标数字 `[1]` + 章末 **References** 列表 | 接近券商研报尾注 |
| 页脚小字来源 | 仅用于免责声明、数据口径 |
| 表格单元格脚注 | 财务表「资料来源：公司公告」 |

**Day 1 stub**：章末 `#heading[References]` + 编号列表即可；精细上标 Day 2 再接 `cite` 包。

## 5. 免责声明（Compliance）

公司报告 Prompt 明确：**不得生成最终目标价、评级、买卖建议或仓位建议**。

PDF 末页（或每页页脚小字）建议固定块：

```
免责声明（草案，需合规复核）

本报告由 HKUST Quant Society Agent 辅助系统生成，仅供内部研究讨论，
不构成任何证券买卖建议或投资建议。报告中的预测、估值与观点可能随时调整。
投资者应独立判断并承担风险。未经书面许可，不得对外传播本报告全部或部分内容。
```

Typst：单独一页 `#pagebreak()` + 小号字（8–8.5pt）+ 灰色 `#5E5E5E`。

```
产业地图 → 立项 → 行业/产业链研究 → 公司全覆盖 → 投资命题 → 结项跟踪
```

| 阶段 | 核心问题 | 主要产出 | 对应 Prompt |
|------|----------|----------|-------------|

| ② 研究立项 | 为什么现在研究、回答什么 | 立项卡 | `02_研究项目立项卡Prompt` |

## 7. 痛点与设计边界（为什么这样拆）

| 痛点 | 现有设计如何应对 | QuantCode Agent 可做什么 |
|------|------------------|-------------------------|
| 会议纪要散乱 | 每阶段有固定产出 + `07_质量检查Prompt` | `model:lit-review` 类结构化 |
| 模型编造数据 | 禁止补造；缺失标 `pending_confirmation` | schema 校验 + assert |
| 估值表难自动生成 | Excel 规范与 Prompt 分离 | Day 1 mock；Day 2 接表格 tool |
| 证据不可追溯 | Reference ID 强制绑定 | `pit-rag` + references.jsonl |
| 商业化阶段夸大 | 证据链分级（送样≠订单≠收入） | Prompt 05 内置规则 |
| 重复立项 / 重复 ID | 元数据规范 + 主表检索 | Blackboard 存 project_id |
| PDF 版式不统一 | HTML/CSS 品牌规范 → Typst | 本文件 + `research-report.typ` |
