## PR 描述建议

### 解决了什么

- 将 QuantEvaluator 从不存在的 HTTP `/evaluate` 假接口改为真实 Python `evaluate(FactorBatch, LabelBundle)`，强制显式标签时序，记录组件版本并生成哈希 artifact。
- FactorSpec 不再冒充 QE 输入；FE MaterializedResult 契约未冻结时显式 UNAVAILABLE。
- 代理因子统计不再能凭数值 `pass` 进入主线 HumanGate；正式登记必须携带 canonical QE 成功证据。
- GitGraph 输出模型覆盖分支窗口、递归依赖文件/包版本变化和错误；无账号路径区分 PERMISSION_DENIED；Windows 凭据走 OS keyring，避免 POSIX `os.getuid()` 崩溃。
- 修复 Windows 下执行锁/流写入、CRLF 发布 hash、POSIX 路径序列化，以及两个前端 `.d.ts` 符号链接被检出为纯文本导致的类型检查失败。

### 如何验证

- 新增/相关窄测试：QuantEvaluator 翻译与 artifact、代理登记拒绝、GitGraph schema、无 token 拒绝、worker 状态、Windows keyring；目标文件 Ruff 通过。
- 后端全量：`1,144 passed / 11 skipped / 1 warning`（102.83 秒）。其中新增的 7 个 skip 是 Windows 无 Unix-domain isolated ssh-agent；4 个既有 skip 仍需真实 LLM 凭据。
- 前端全 workspace typecheck：Turbo `29 successful / 29 total`；QuantCode 组件：`126 passed / 0 failed`。
- Headless 尚未执行：`localhost:4444` 拒绝连接，且 `frontend/packages/app/AGENTS.md` 禁止代理启动或重启 app/server。需要操作者从仓库根目录运行 `bun run dev:quantcode`；随后在 `frontend/packages/app` 的 PowerShell 中设置 `$env:PLAYWRIGHT_BASE_URL='http://localhost:4444'`、`$env:PLAYWRIGHT_EXTERNAL_SERVER='1'`，再运行 `bunx playwright test e2e/quantcode/workspace.spec.ts`。
- 以上数字只用于回归比较；真实账号、真实数据和真实组件链仍按矩阵单独验收。

### 还缺什么外部条件

- 八组各至少一个真实 GitHub 账号及最小权限 token，另需一个明确无权限账号作对照。
- DataAccess 可用数据环境、CredentialProvider、数据快照和显式 forward-return LabelBundle 来源。
- FactorEngine 固定 wheel 或稳定私有 Git 拉取通道，以及真实 MaterializedResult artifact。
- 组件负责人冻结 `DataAccess output → FE request`、`FE MaterializedResult → QE FactorBatch`、`DataAccess target return → QE LabelBundle` 三个版本化 seam。
