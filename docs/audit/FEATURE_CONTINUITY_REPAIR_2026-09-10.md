## 后续：缓存项目触发“无法重新加载 服务器”

截图中的“服务器”是旧本机项目 `/Users/hendrixchen/Desktop/服务器` 的目录名。缓存同时保留正确的远程管理员目录 `/srv/quant/users/quantadmin`，没有删除或混写这两份项目配置。

根因：`child(directory, { bootstrap: false })` 本应只读取缓存元数据，却仍创建了默认启用的 path/LSP/provider 查询；收到 server.connected/global.disposed 事件后，刷新队列又将这些未打开的目录全部进行完整初始化。失败来自没有有效组织身份的本机 sidecar，并非当前 Server C 管理员宿主。

修复：缓存元数据读取保持被动，明确打开工作区才启用目录查询；全局重连仅将已启用的目录加入刷新队列，初始化入口也检查同一状态。显式请求 MCP 的行为保留。项目、任务与登录缓存没有清除。

新增回归先在旧代码上失败，修复后通过，并验证明确打开项目后仍正常加载。前端全套 674 项通过，类型检查与桌面完整构建通过。

该修复部署到桌面后，启动观察 98 秒：服务就绪，`Failed to load sessions` 与 `Failed to finish bootstrap instance` 均为 0。核验记录保存在本地 `.quantcode/cached-project-reload-verification.json`；本轮没有修改远端服务或删除缓存项目。
