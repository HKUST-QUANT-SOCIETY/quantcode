# 任务与连续对话修复（2026-09-11）

## 根因

首页 `QuantCodeHome.startResearch` 每次提交都调用 `tabs.newDraft(..., task, {submit: true})`，把首页当作聊天框使用时必然不断创建任务。项目选择还启用了 `useDefault`，工作目录在提交前不够明确。已有会话的原生 `promptAsync` 本身使用原 session ID，没有必要引入第二套任务存储。

`QuantCodeTaskContext.load` 在每次需求变化时自动执行能力目录和组织知识检索，即使用户只是问模型身份。它生成的工具记录出现在正式模型回答之前。

## 修改

- 首页展示任务列表和每项的真实目录。选择已有任务打开原会话；只有明确点击新建才选择目录、输入任务名、创建原生 Session。
- 创建任务不发送消息；旧草稿文字继续保留为未发送内容。会话页显示可复制的工作目录。
- QuantCode 不再调用模型自动命名任务，不再在消息入口自动执行目录/知识检索。原有组织工具、写入检查、方案与审批校验保留。
- 组织网关在本地并发拒绝时返回绑定请求 ID 的 `not-started` 响应标记。宿主只接受固定、由部署配置指定的网关 URL；上游 429、其他 URL、网络错误和缺失回执都不能释放额度。
- 原生流失败处理接受上述明确回执并结算零用量，正常模型消耗仍使用供应商 usage 结算。
