一、LangGraph 是什么？

LangGraph 是一个用「图（Graph）」来编排 AI Agent 工作流的 Python 框架。 它不负责「聊天」，而是负责：多步骤任务怎么跑、状态怎么存、失败了怎么恢复、人怎么介入。

官方一句话：Low-level orchestration framework for building stateful agents —— 构建有状态、可长期运行、能从失败中恢复的 Agent 的底层编排框架。

由 LangChain 团队维护，GitHub 约 36k+ stars（langchain-ai/langgraph）。 安装：pip install -U langgraph

二、为什么要用 LangGraph？（解决什么问题）

普通 LLM 调用是「一问一答」。真实投研 / 工程任务往往是：

  • 很多步（拉数据 → 算因子 → 回测 → 风控 → 发 PR）
  • 要记中间结果（不能全靠对话上下文）
  • 会失败、要重试、要暂停等人审批
  • 多个子 Agent 分工协作

LangGraph 专门解决这类长流程、有状态问题，而不是替代 Cursor / OpenCode 的单轮对话。

三、核心概念（必懂）

3.1 Graph（图）

整个 Agent 工作流是一张有向图：

┌─────────┐ │ START │ └────┬────┘ ▼ ┌─────────┐ 条件分支 ┌─────────┐ │ Node A │ ───────────────► │ Node B │ │ (拉数据) │ │ (算因子) │ └────┬────┘ └────┬────┘ │ │ └──────────┬──────────────────┘ ▼ ┌─────────┐ │ Node C │ ← Human Gate：等人批准 │ (风控) │ └────┬────┘ ▼ [ END ]
  • Node（节点）：一个函数 / 一个 Agent 步骤（做一件事）
  • Edge（边）：节点之间的流转（下一步去哪）
  • Conditional Edge：按状态决定走哪条分支（if/else）

3.2 State（状态）

图里有一个共享的 State 对象（通常是 TypedDict 或 Pydantic）， 每个节点读取 State → 干活 → 写回 State。 

# 概念示例（简化）
class AgentState(TypedDict):
    messages: list
    task_id: str
    artifacts: dict
    status: str

这就是 LangGraph 版的「黑板」—— 所有节点通过 State 交换信息，而不是互相私聊。

3.3 Checkpoint（检查点）

LangGraph 可以把每一步的 State 持久化到磁盘/数据库（checkpoint）。 进程崩溃、服务重启后，用 thread_id 加载上次 checkpoint 继续跑。 

# 概念：编译图时开启 checkpointer
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()
graph = builder.compile(checkpointer=checkpointer)

# 恢复执行
config = {"configurable": {"thread_id": "session-abc"}}
graph.invoke(input, config=config)

重点：checkpoint 存的是状态快照，不是完整 event log。QuantCode 的 BlackboardState 设计参考了这一点。

3.4 Subgraph（子图）

大图里可以嵌小图。例如「fundamental 流」是一个 subgraph，「factor 流」是另一个。对应 QuantCode 的 6 套 Compose 流。

四、LangGraph vs 其他方案

vs 普通 ChatGPT / Cursor

单轮对话，无持久状态机。LangGraph 管多步编排 + 状态恢复。

vs Temporal / Airflow

传统工作流引擎偏确定性任务；LangGraph 专为 LLM + 工具调用 设计，节点可以是 Agent。

vs OpenCode / Claude Code

OpenCode 是交互式 coding agent 载体；LangGraph 是后台编排引擎。QuantCode 在 OpenCode 之上加 LangGraph 式契约。

vs LangChain Chains

Chain 是线性管道；LangGraph 支持循环、分支、并行、人机协作，更适合复杂 Agent。

五、最小可运行示例（理解用）

from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# 1. 定义状态
class State(TypedDict):
    step: int
    log: list[str]

# 2. 定义节点（每个节点是一个函数）
def step_a(state: State) -> State:
    return {"step": 1, "log": state["log"] + ["fetched data"]}

def step_b(state: State) -> State:
    return {"step": 2, "log": state["log"] + ["computed factor"]}

# 3. 建图
builder = StateGraph(State)
builder.add_node("fetch", step_a)
builder.add_node("compute", step_b)
builder.add_edge(START, "fetch")
builder.add_edge("fetch", "compute")
builder.add_edge("compute", END)

graph = builder.compile()

# 4. 运行
result = graph.invoke({"step": 0, "log": []})
print(result)
# {'step': 2, 'log': ['fetched data', 'computed factor']}

加上 checkpointer 后，每一步都会存档，可随时 resume。

## LangGraph 调研汇报（5 分钟）

### 1. LangGraph 是什么
- 有状态 Agent 的图编排框架，核心：State + Node + Checkpoint

### 2. 对 ComposeTask 的建议
- 借鉴 LangGraph 的父子图分解 → task_id 层级 T1.2.3
- 借鉴 status 状态机 → open/in_progress/blocked/done/abandoned
- 建议增加/保留：dispatch_count 上限、terminal outcome 约束

### 3. 对 BlackboardState 的建议
- 借鉴 checkpoint 外化状态 → 不依赖 LLM 上下文记忆
- 五层 scope 对应不同生命周期（GLOBAL → TASK）
- WritePolicy 明确读写权限，防止跨组污染

### 4. 我们不直接上 LangGraph 的原因
- QuantCode 跑在 OpenCode fork 上，用 Pydantic 契约 + 文件持久化
- 需要 6 组隔离、dedupe 保险栓等 LangGraph 原生不提供的约束
