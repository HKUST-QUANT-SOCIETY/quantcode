## 本阶段最后一轮补齐的入口

- Command 沿用原目录构建逻辑；迁移模式不使用跨登录目录缓存，lazy template 每次消费固定原登录重验。列表不拉取 MCP 模板正文。
- MCP 服务说明也按当前已发布工具/内容目录过滤，说明读取期间校验连接、发布版本和完整 owner。只读 Shell 先取读权限，只有真实目标非空才取写权限。
- 原生重复调用检测使用现有三次阈值，按当前真实用户请求跨模型轮次读取工具尾部；失败调用不丢弃，自动压缩重放不作为新用户需求。命中经既有 error/idle/cleanup 路径停止。
- 项目发现复用 Core Git/Project resolver，通过受控 AppProcess 和截止授权根的 FS 服务执行；仓库自报 `.git/opencode` 不再触发原生会话迁移。非Git/空仓库按真实工作区建立标识，项目列表与目录映射按当前授权投影，不显示其他工作区路径。
- Git 只读查询复用既有解析器，禁宿主凭据/外部diff/textconv/hooks/网络与任意Git子命令；专用初始化独占创建新 `.git`，只开放其元数据写入。工作区参数不能选择未知远端 adapter 代理宿主请求。
- VCS 裸补丁入口必须绑定真实任务工具记录并经原生方案/回执/文件写入；当前没有专用 `vcs_apply` 产品工具或桌面调用，故不能描述为独立功能已可用。原生 write/edit/apply_patch 是当前已接通的编辑路径。
- 快照保留 Git 对象/树和 diff 表示，私有对象库按 owner/权限/工作区分开；捕获从授权文件句柄读取字节，不执行源仓库 filters/hooks。恢复传入 native session，走方案/回执和二进制文件操作。上游公共 ShareNext 不会自动外传 QuantCode 任务。
- 旧 worktree 创建/重置/删除入口缺少组织工作区登记与版本上下文，迁移模式明确拒绝，不运行其任意 startCommand；现有登记工作区及普通子会话继续使用同一引擎。这是该旧入口的兼容边界，不是新建隔离工作区功能的完成证明。
