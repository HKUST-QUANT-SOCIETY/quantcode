## 2026-09-09 取消与任务树回修（源码待验）

父任务停止改由真实 `SessionTable.parent_id` 遍历后代并取消既有 Runner，因此覆盖旧 BackgroundJob 已完成、子会话再次打开执行的情况。每条关系仍核对完整 owner、root、parent、project、workspace 和目录；异常归属不被猜测取消。停止操作只合并同一 Runner 的在途取消，不缓存已完成停止结果。

Shell 的整体准入/执行退出释放原 ready 信号，避免还未进入 shellImpl 就被取消时永久等待。任务树停止采用短暂进程内准入屏障及原任务 epoch：后台完成/失败通知、原生输入事件提交和子任务创建都核验原执行上下文，迟到通知不重启已取消父任务，迟到创建不落下新子会话；普通失败清理仅失效需要取消的后代，保留正常失败通知。

桌面详情复用 `session.children` 和 `session.status` 显示完整后代层级与活动数量；父任务空闲但后代活动时仍提供“停止任务树”。错误不会被普通 SSE 刷新静默清除，停止响应返回后再次核对活动状态。组织投影页面仍不代理别的宿主执行。

新增回归源码覆盖原生 Session/Event/Runner、Shell 准入失败、同 Runner 再启动、父子归属、迟到创建和真实 TaskTool/BackgroundJob/Prompt 通知链。外部身份使用隔离 fixture，模型执行有意省略；尚未运行任何用例，实际进程与跨宿主行为不能据静态复审记为通过。

## 审批响应丢失后的核对（源码待验）

桌面通过固定 `quantcode.nativeGate.read` 查询原请求。提交前仅保留按宿主/成员/组/工作区隔离的请求 ID 与原摘要；响应丢失或重新登录后读取权威状态，未知结果不重发，仍 pending 且摘要一致时才开放重试。已记录决定、过期、取消和当前授权失效分别展示，不把失败提示写成“审批未保存”。

网关复用原 Gate 存储、原决定链和当前 SessionContext。对本人已处理记录，原审核者以完全相同的当前成员/组/角色/工作区/GitHub/scope重新认证后可以核对历史结果；旧 owner/审核会话失效保持 `valid=false`，不能借历史读取复活执行权限。普通读取和其他成员的访问仍走原授权规则，跨成员读取保留审计。相应重新登录、结果缓存及拒绝场景仅编写了回归源码，未运行。

同宿主审核接口不会转发到未知远端 URL；Admin 须连接任务的受信执行宿主核对。组织索引本身不成为执行/身份代理。网络或凭据型旧业务组件在当前隔离兼容器中明确不可用，须走已发布组织服务，不能回落无限制归档执行。
