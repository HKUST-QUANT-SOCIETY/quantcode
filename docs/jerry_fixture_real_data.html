Fixture 真实数据需求清单

Owner：刘炽（options / fundamental / strategy）· 用途：把现有 fixture 从「手写假数」升级为「从真实源抽样固化」· 更新：2026-07-10

先回答你的问题： 是的——下面这份清单专门用于 fixture，不是生产全量接入清单。

Fixture = 测试/demo 用的小样本快照。正确做法是：向各组/基建要一小段真实数据 → 脱敏/截断 → 写进 tests/fixtures/ 或 data/sample_options/。
不是让你现在接全市场 API；也不是继续纯手编假 JSON（除非对方暂时给不了）。

0. 概念对照

概念 是什么 你要做什么
Fixture 仓库里的样例输入文件（JSON/CSV/diff） 用真实源抽样后固化进仓库
真实数据来源 服务器共享盘 / Chroma / 各组跑数产物 找对应 owner 要「一小段可公开进 repo 的样本」
生产接入 tool 直接读全量库/API Week 2+；本清单不覆盖全量

2. P0：你自己三条线 —— Fixture 要的真实数据

2.1 Options 曲面 Fixture

目标文件：data/sample_options/gc_options_merged_sample.csv（可另存 _from_prod_YYYYMMDD.csv）

向谁要 真实数据源 抽多少就够做 fixture
基建组 + 期权组 /srv/quant/shared_data/options/merged/gc_options/ 某一日 parquet/csv 1 个交易日，约 20–200 行（多 strike × call/put）即可

Fixture 里必须保留的列：

  • datetime / file_date
  • underlying（如 GC）
  • expiration
  • strike_price
  • instrument_class（call/put）
  • bid_px, ask_px, mid_px（或 close）
  • symbol（建议）
  • volume（可选）

额外建议同日抽一份：对应期货价 1 行（forward），可放进同目录小 JSON，避免 BS 用 strike 中位数凑。

脱敏：若政策不允许原样进 Git，可对价格做微小噪声，但字段与日期关系要真实。

2.2 Fundamental PIT 语料 Fixture

目标文件：tests/fixtures/pit_corpus_sample.json

向谁要 真实数据源 抽多少就够做 fixture
基建组（Chroma）+ 基本面组 研报/公告语料库或 Chroma collection 导出 4–8 篇同一 ticker（如 2097.HK）；另保留/构造 1 篇 published_at 在未来的文档专测 PIT

每条文档字段（fixture JSON）：

  • id（必须）
  • published_at（必须，ISO 日期）
  • title（必须）
  • snippet 或正文截断 200–500 字（必须）
  • source（必须，券商/公告名）
  • url（可选，可置 null）
  • score（可选，检索分；没有可事后算）

注意：进仓库的应是脱敏摘要，不要整篇未授权研报全文。

2.3 Strategy 候选信号 Fixture

目标文件：tests/fixtures/strategy_backtest_result.json

向谁要 真实数据源 抽多少就够做 fixture
因子组 / 模型组 一次真实 AutoEval / ModelSpec 跑数后的信号列表，或 Blackboard 导出 3–6 条候选信号 + 1 个 as_of_date + universe

Fixture 字段：

  • strategy_name, as_of_date, universe
  • candidates[]：signal_id, source_group, weight_hint
  • （可选）附带真实回测摘要数字，便于对照 stub

5. 你要出去「要数」时的最小话术

基建组

  • 给我 merged/gc_options 任意 1 天可导出样本（20–200 行）进 fixture
  • 同日 futures 结算价 1 行
  • Chroma/语料：导出 5–8 条含 published_at 的摘要（可脱敏）

期权组

  • 确认字段与 DataStructure.md 一致；mid 用哪一列算 IV

基本面组

  • 1 个 ticker 的 4–8 篇摘要 + 1 期财务关键指标（含发布日）

因子 / 模型组

  • 3–6 条真实信号（id / source_group / weight_hint / as_of_date）

6. 验收标准（Fixture 升级算不算完成）

  • 文件仍在 repo 内，demo/测试不依赖外网
  • 字段能过对应 Pydantic schema
  • 来源可追溯（在 README 或 JSON 里写 source / as_of / note: sampled from …）
  • PIT fixture 仍保留至少 1 条应被过滤的未来文档
  • 未把未授权全文研报、密钥、完整生产库塞进 Git
