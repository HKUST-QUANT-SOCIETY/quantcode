# QuantCode 两步登录

2026-09-10。本文描述当前源码实现；成员只需持有已登记公钥对应的本地私钥。A/B/C 地址内置，不要求填写 URL、端口或访问密码。

## 成员操作

有效会话：打开应用自动恢复所选研究宿主的 SSH 隧道，核验已有会话，进入工作台。恢复不会再次签名，也不会延长过期会话。

重新登录：

1. 点击「重新登录」，系统文件选择器选择私钥。例：`qc-chenzhenhong_ed25519` 解析为 `qc-chenzhenhong`。通用名称如 `id_ed25519` 无法确定成员时，仅询问一次用户名，并按公钥指纹保存在本机。私钥加载到本机 SSH Agent，正文不上传。
2. 应用依次 SSH 探测 A/B/C，读取 `groups` 和本人私有 `~/.quantcode/test-v1/connection.json`。界面列出「组 × 服务器」，点组选项后签发该组的正式会话、切换研究宿主、记录个人工作目录并直接进入工作台，没有另一个服务器选择或进入按钮。

未登记或尚未开通个人宿主的服务器显示不可用原因，其余服务器继续可选。取消文件选择没有副作用，也不显示用户名错误。

## 组和身份来源

经用户确认：Linux 组用于发现和排序，组织名册补足并限制清单。已有研究账号可以保持仅有 `qc-<actor>` 私有 Linux 组；无需增加 Linux 业务组或扩大文件系统权限。Linux 的 sudo 等组不会变成 QuantCode 权限。

账号、角色、工作目录、资源权限来自组织网关。组选项必须属于宿主登记公钥在名册中的授权组。所选组被写入一次性 challenge 的签名内容；verify 使用宿主保存的同一个组，不能在认证期间换组。旧宿主若不能签发所选第二业务组，会在签名前明确要求升级，不能用前端状态假装成功。

## 内部链路

```mermaid
sequenceDiagram
  participant U as 成员
  participant D as 桌面主进程
  participant H as 个人研究宿主
  participant G as 组织网关
  U->>D: 选本地私钥
  D->>D: 解析/记住用户名，加载本机 Agent
  D->>H: 依次 SSH A/B/C，读取 groups 和私有连接信息
  D->>H: 建立回环隧道，读取已登记身份
  H->>G: 查询公钥对应的授权组
  D-->>U: 组 × 服务器清单
  U->>D: 点选一项
  D->>H: challenge（公钥身份、授权组）
  H->>G: 请求组绑定 challenge
  D->>D: 本机 Agent 签名
  D->>H: verify（challenge ID、签名）
  H->>G: 验证签名、名册和所选组
  H->>H: 保存私有会话凭据，撤销被替换的旧会话
  D-->>U: 真实身份核验通过，直接进入所选工作区
```

本机持久记录只保留最近选择的服务器 ID、私钥路径、用户名、指纹、组和用于恢复的本机端口等元数据。私钥路径不由 renderer 传入。组织 token 仍仅在研究宿主的私有会话文件中；网关保存 token 哈希。宿主 HTTP 访问凭据沿现有桌面服务器连接机制提供给 SDK，界面不要求成员填写。

退出登录沿原有身份桥撤销网关会话。关闭应用清理本机隧道，不撤销仍有效的身份。任务执行始终重验网关权限和任务归属。

## 管理员配置

每位成员必须已有独立 Linux 账号、登记公钥、个人研究宿主、组织名册和私有连接文件。连接文件遵循 `scripts/write_test_v1_connection.py` 的结构，必须属于当前 SSH 用户；文件内的目标地址不会覆盖应用内置服务器，隧道目标固定为该服务器的回环研究端口。

桌面需有系统 OpenSSH 和可用的本机 SSH Agent。Windows 的首次系统组件/服务配置仍遵循平台安装说明。第二业务组选项需要研究宿主支持本次新增的组绑定 challenge 参数。
