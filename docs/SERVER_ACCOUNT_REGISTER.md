# 维护本地服务器账号登记

从仓库根目录运行：

```sh
python3 scripts/sync_server_account_register.py
```

默认通过本机已有的 `qs-data`、`qs-compute`、`qs-gpu` SSH 配置，以 `ubuntu` 的只读管理命令采集 A/B/C。服务器需有 Python 3、OpenSSH；C 的名册解析使用现有 PyYAML。命令不创建账号、不追加公钥、不授予业务组，也不重启服务。

生成文档为 `docs/ops/SERVER_ACCOUNT_REGISTER.md`。原始快照、人工登记和逐次历史保存在 `.quantcode/server-account-register/`，其中包含内部账号元数据，不应随工具代码发布。

## 核验口径

每把公钥分别检查旧账号登记、工作区描述、目标 SSH 公钥、研究账号注册表、可读连接 profile、宿主公钥列表和两份正式名册。宿主运行状态及身份 HTTP 接口另列，不能以接口返回 200 替代 SSH 配置完整性。

“本人完整登录”只来自独立人工验收记录。没有设备系统、实际客户端版本、时间、账号、公钥及证据来源时，不标作完整验收通过。存在服务器会话或发布构建成功，也不代表某位成员已升级并登录。

采集错误与业务错误分别记录：

- 整台服务器采集失败，保留历史数据，但同时显示本次失败时间、显示数据时间和最后成功时间；涉及它的链路记为当前未核验。
- 一个账号、名册或进程配置读取失败，保留其他账号结果。
- 身份接口不可用或配置有缺项，仍生成本次文档，不因业务异常留下旧的“全部正常”页面。
- 采集失败返回退出码 1，报告仍生成；正常采集中的业务缺项写入表格。人工登记文件本身无法解析时则明确报错并保留旧文档。

## 人工确认与待办

复制 `configs/server-account-register.example.json` 为本机状态目录中的 `annotations.json`，填写实际信息并移除示例项。服务器账号标识使用 `server-b:username`，密钥标识使用完整 `SHA256:...` 指纹；K 编号只用于当次文档导航。

- `actors`：姓名、确认来源、责任人。历史入组表标签与本人确认应写明区别。
- `accounts`：人员归属、待开通/无需产品入口/待确认状态、责任人、下一步和完成时间。缺少责任人时保留“管理员待指派”，不替他人作出确认。
- `keys`：本人确认的常用/备用用途、启用/停用状态和确认来源。服务器仍接受一把公钥，不等于本人确认它仍在使用。
- `login_checks`：实际系统、客户端版本、结果、失败阶段、时间和证据来源。只能确定成员身份而不知道此次公钥或 SSH 用户名时，相应字段留空，只作为成员级反馈，不绑定为某把密钥的验收。

root、ubuntu 和隔离测试账号单独分类，不作为漏开的普通成员。未登记成员的身份、在用密钥或业务组尚不明确时，先记录待办，不能仅凭相似姓名或 Linux 管理组自动扩大产品权限。

## 离线复核、差异和来源

```sh
python3 scripts/sync_server_account_register.py --offline \
  --state-dir /path/to/local-snapshots --output /path/to/report.md
```

离线模式不连接 SSH 或 GitHub。支持旧格式快照和新格式的逐台采集结果。每次运行保留历史快照、稳定标识下的账号/公钥/组授权变更、文档摘要、工具提交和脚本哈希。采集失败不会被算作账号或公钥删除。

SSH 别名可以用 `--host server-a=your-data-host` 覆盖；管理员账号可用 `--ssh-user` 指定。若本机有 GitHub CLI，在线同步还会查询公开发布版本；查询失败单独标记，不阻塞服务器登记。
