# QuantCode Test V1.2 · 登录修复

版本：`1.2.0-test.2`。本版保留 Test V1.2 的工作台功能，修复普通成员的 SSH 入口和异常恢复。

## 更新内容

- 既有 SSH 账号可通过管理员安装的连接描述入口发现实际研究工作区，成员无需输入内部研究账号。用户名和公钥仍需与组织登记匹配，映射不自动追加或替换公钥。
- 复用系统 SSH 配置和已有 Agent 身份，支持 PEM、无扩展名 OpenSSH 以及已在 Agent 解锁的加密私钥；未解锁时提供本机终端入口。
- 短暂断网后继续核验身份，SSH 恢复和窗口聚焦会触发重验；权限尚未核验时禁止受限操作。
- 认证结果不确定时提供核对入口。取消进入后，已经签发的会话会显示“继续进入工作区”及“退出本次登录”，不再伪装成已取消认证。
- 启动先呈现可操作界面，后台恢复连接可停止，恢复过程有总时限；上次未确认的登录不会自动进入工作区。
- 重新探测时读取最新宿主配置并替换旧连接，更新密码或端口无需重启客户端。
- 使用组织预置的 A/B/C 主机公钥校验服务器身份；“断开”按钮明确为“退出组织会话”。

## 安装与验收

[下载安装包](https://github.com/HKUST-QUANT-SOCIETY/quantcode/releases/tag/quantcode-v1.2.0-test.2)。退出旧版后，安装对应架构的新包。Mac Apple Silicon、Mac Intel 和 Windows x64 均提供测试包；本版仍未做平台签名，自动更新关闭。

1. 使用原私钥或已有 Agent 身份，填写原来的 SSH 用户名，检查是否列出正确工作区。
2. 加密私钥先在本机终端解锁，然后点击重新探测，不重复选择文件。
3. 在连接恢复期间确认登录入口可操作，网络恢复后身份显示能重新就绪。
4. 点击组后取消进入，核对会话状态，再选择继续进入或明确退出。

如果显示“SSH 已连接，但公钥尚未关联工作区”，请管理员核对本次公钥指纹。客户端不会绕过登记，也不会自动把某台服务器的 SSH 公钥授权给其他服务器。

## 服务端配套

管理员使用 `scripts/install_ssh_workspace_discovery.py` 安装固定的 `quantcode-connect` 描述命令及受管理的每 UID 连接映射。脚本先输出计划摘要，应用时校验摘要并保留旧文件备份；不会修改 Linux 账号、UID、公钥、研究目录或运行服务。旧的本人 profile 读取路径继续兼容。

连接映射以现有名册、已开通的研究账号和公钥登记为依据。跨服务器目标仍须通过 SSH 公钥认证和组织挑战签名，描述文件不能赋予角色或他人的工作区权限。
