# QuantCode Test V1.2 · 用户名记忆与工作区发现修复

版本：`1.2.0-test.5`。

## 客户端更新

- 本次明确输入和已确认的用户名优先于旧 SSH 配置。不同服务器上的验证成功账号分别保存；重开应用后不会再次被旧配置覆盖。
- 连接详情和失败信息显示实际尝试的服务器、用户名及来源。没有确定用户名时先询问，不把本机操作系统用户名当作已确认的服务器账号。
- 访问过个人宿主后，客户端记录该宿主已登记公钥对应的工作区发现信息。换用它列出的备用钥匙时，可以回退到同一研究用户名，并重新执行完整 SSH 和名册认证。
- 保留 `test.4` 的 Windows SSH Agent 检测、系统授权启用及启用后继续登录流程。

本版不向旧服务器追加备用公钥，也不扩大业务组、文件权限或管理员角色。新电脑尚无工作区发现记录时，备用钥匙首次登录仍需确认可用研究用户名，或先用常用钥匙完成工作区发现。

## 登记维护工具

采集与生成脚本已进入仓库 `scripts/`。现在按每把公钥核对目标 SSH 登记、账号注册表、profile、宿主公钥和正式名册，并将配置完整性、接口可用性、本人完整登录实测分开。

部分服务器或账号采集失败时仍生成报告，历史值明确带原时间；接口异常不会让同步工具留下旧的正常报告。支持人工责任人/密钥用途/客户端版本登记及历史差异。见 [维护说明](../SERVER_ACCOUNT_REGISTER.md)。实际服务器数据和人工登记留在管理员本机，不包含于安装包或工具示例。

## 安装与检查

[下载修订包](https://github.com/HKUST-QUANT-SOCIETY/quantcode/releases/tag/quantcode-v1.2.0-test.5)。完全退出旧版后安装对应架构的新包；Server C 服务无需为本次客户端修正更新。

1. 在应用确认正确 SSH 用户名，关闭并重开，检查是否仍使用该用户名。
2. 原 SSH 配置有旧用户名时，连接详情应显示实际选择及来源。
3. 使用常用钥匙发现工作区后换用宿主已登记的备用钥匙，核对它是否能找到同一研究账号。

仍为未做平台代码签名的内部测试预发布，自动更新关闭，需手动安装。成员公钥归属、启停或业务组尚未确认的登记缺项，继续由组织管理员按确认结果处理。
